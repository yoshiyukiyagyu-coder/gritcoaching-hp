## 2. ブログ記事タイトルの後ろの社名を短くする

今は全記事のタイトルの最後に「 | グリットコーチング・ジャパン株式会社」（17文字）が付いており、検索結果で記事名の後半が切れています。設定1か所で全記事に反映できます。

1. 管理画面 → **All in One SEO** → **検索の外観** → **コンテンツタイプ** タブ
2. 一覧の **ブログ**（URLが `/blog/blog/〜` の投稿タイプ）を開く
3. **タイトル** 欄を次のように変更して **変更を保存**

| 変更前（例） | 変更後 |
|---|---|
| `#post_title #separator_sa #site_title` | `#post_title ｜GRITcoaching` |

- `#site_title`（サイト名）そのものは **設定 → 一般** で変えないでください。会社情報（構造化データ）の名前にも使われているためです。
- 保存後、記事を1本開いて、ブラウザのタブにタイトルが「〜｜GRITcoaching」と出るか確認します。出ない記事は、その記事の AIOSEO 設定でタイトルが個別に上書きされています。その記事の「投稿タイトル」欄を `#post_title ｜GRITcoaching` に直してください。
- 「お知らせ」（`/blog/news/〜`）など、ほかの投稿タイプも同じ形に揃えてかまいません。

## 4. 申し込み完了（thanks）ページを検索に出さない

申し込み完了ページは検索から来る人に見せるページではないので、「インデックスしない」設定にします。設定するとサイトマップからも自動で外れます。

**2026-11-09 設定済み（20ページすべて）。** ログアウト状態で全ページに noindex が付いていること、サイトマップに thanks ページが1つも載っていないことを確認しました。

1. **固定ページ** → 対象のページを開く
2. **AIOSEO 設定** → **詳細** タブ → **ロボット設定**
3. **デフォルト設定を使用** をオフにして、**インデックスなし（No Index）** にチェック → **更新**

**対象（20ページ）**
```

/lp006/thanks/  /lp007/thanks/  /lp008/thanks/  /lp009/thanks/  /lp010/thanks/

/lp016/thanks/  /lp017/thanks/  /u12-school/thanks/  /u15-lp01/thanks/  /u15-school/thanks/
```

### LP用テンプレートの thanks ページ（17ページ）

20ページのうち17ページは、U15 と同じLP用テンプレート（`page-lp.php`、`wp_head()` を呼ばない）で表示されています。このテンプレートでは、AIOSEO で「インデックスなし」にしても `<meta name="robots">` がページに出ません。

| テンプレート | ページ | noindex の伝え方 |
|---|---|---|
| `page-lp.php` | `/lp001/thanks/`〜`/lp016/thanks/`、`/u15-school/thanks/` | プラグイン **GRIT LP SEO Head**（1.1.0）が `X-Robots-Tag: noindex` ヘッダーを送る |
| `page-blank.php` | `/lp017/thanks/`、`/u12-school/thanks/`、`/u15-lp01/thanks/` | AIOSEO が `<meta name="robots" content="noindex, …">` を出す |

- プラグインは、`page-lp.php` のページで AIOSEO の「インデックスなし」がオンのときだけヘッダーを送ります。どのページを noindex にするかは、これまでどおり AIOSEO の設定で決めます。
- **このプラグインを停止・削除すると、上の17ページの noindex が効かなくなります**（U15 のタイトル・説明文も戻ります。3章参照）。
- 確認方法: ブラウザの開発者ツール →「ネットワーク」でページを開き、レスポンスヘッダーに `X-Robots-Tag: noindex` があるかを見ます。ターミナルなら `curl -sI https://gritcoaching.co.jp/lp001/thanks/ | grep -i x-robots-tag` でも確認できます。
- 新しくLP用テンプレートで thanks ページを作ったときも、AIOSEO で「インデックスなし」をオンにするだけで、このヘッダーが付きます。
- 検索結果からすぐ消したい場合は、Search Console の「URL検査」でそのURLのインデックス登録をリクエストします（Google が再確認したあとに外れます）。

- **広告用LP（`/lp001/`〜`/lp017/`、`/u15-lp01/`、`/u12-short-202612/`）はこの手順では触りません。** 広告で使っている場合、検索に出すかどうかは担当者と相談して決めてください。内容がほぼ同じLPが多い場合は「インデックスなし」にするのがおすすめです。

## 8. 記事の説明文の自動補完（2026-11-09 実施）

新しく公開したブログ記事4本とお知らせ1本で、検索結果用の説明文（`<meta name="description">`）が出ていなかった。原因は、AIOSEO の説明文欄が空のままだったこと。この AIOSEO 4.6.1.1 は「説明文を自動生成しない」設定になっているため、欄が空だと説明文は何も出力されない。

- 対象だった記事: `elementary-soccer-slow-runner-tips`、`soccer-parents-sideline-coaching`、`junior-high-soccer-players-who-improve`、`elementary-soccer-home-practice-menu`、お知らせ「会社設立のご案内」
- 対応: プラグイン `grit-top2026`（バージョン 202611092050）に、ブログ・お知らせの記事で AIOSEO が説明文を出さないときだけ、本文に埋め込んだ説明文（`META_DESCRIPTION`）を出力する処理を追加した。埋め込みがない記事は、抜粋欄か本文の冒頭を160文字以内で使う。SNS用の説明文（og / twitter）も、空なら同じ文で補う
- 確認: 全18記事で説明文がちょうど1つずつ出ている（重複なし・エラーなし）。もともと説明文欄が入っていた13記事の文は変わっていない
- 今後: 新しい記事は、AIOSEO の説明文欄が空でも自動で補われる。ただし、検索結果で見せたい文が決まっている記事は、AIOSEO の説明文欄に入れておくのが確実（欄に入れた文が優先される）
- プラグインの元データは `~/claude/grit HP`（`tools/build_wordpress.py` で生成）。同じ日に、表示速度の改善（写真の WebP 化、トップと一覧で使っていない CSS・JS の読み込み停止）も行った

## 9. 技術SEOの点検と、SNSシェア用画像（2026-11-10）

「Rank Math SEO を入れて OGP・canonical・構造化データ・サイトマップを整える」という提案を検討したが、**Rank Math は入れない**ことにした。このサイトでは AIOSEO（5.0.5）がすでに同じものを出力しているので、入れるとタグがすべて二重になる。SEO プラグインは AIOSEO の1つだけにする。

### 本番の出力を確認した結果（ログアウト状態、トップと記事 `elementary-soccer-slow-runner-tips`）

| 項目 | 状態 |
|---|---|
| canonical | 各ページに1つずつ、正しいURL |
| OGP / X（Twitter）カード | 出ている。記事はアイキャッチ画像が `og:image` になる |
| 構造化データ（JSON-LD） | AIOSEO が Organization・WebSite・WebPage・BreadcrumbList・Person を出力。記事本文に埋め込んだ Article・FAQPage もある |
| XMLサイトマップ | `/sitemap.xml`（AIOSEO が生成）。robots.txt にも記載あり |
| 説明文 | 出ている（8章） |

### 残っている課題

1. **著者情報が辻尾さんになっていなかった → 2026-11-10 対応済み**
   記事の投稿者は WordPress ユーザー `auto_write`（自動投稿用、権限は編集者）で、プロフィールが空だった。そのため AIOSEO の構造化データでは著者（Person）が「auto_write」になり、本文の Article にある著者「辻尾真二（GRITcoaching 代表 / 元プロサッカー選手）」と食い違っていた。
   対応: `auto_write` のプロフィールを REST API（`POST /wp-json/wp/v2/users/me`、自動投稿と同じアプリケーションパスワード）で変更した。姓「辻尾」・名「真二」・ニックネームと表示名「辻尾真二」、Webサイト `https://gritcoaching.co.jp/`、プロフィール情報（経歴）を入力。変更前は表示名が auto_write で、ほかの欄は空だった。
   確認: 記事の構造化データの著者（Person）が「辻尾真二」になり、Article の著者と一致した。全記事が同じユーザーなので全記事に反映される。ログイン名と自動投稿の設定は変えていない。
